## Route the audio you actually want

IterVC takes a non-destructive copy of selected application audio. Your apps keep playing normally through their existing Windows output while IterVC builds a separate mix for another destination.

## Do you need a virtual cable?

<div className="itervc-choice">
  <div className="itervc-choice__card itervc-choice__card--primary">
    <span className="itervc-choice__label">Main use case</span>
    <h3>Yes — when another app must receive the mix as a microphone</h3>
    <p>Use a virtual cable when Discord, VRChat, OBS, TeamSpeak, or another application must receive IterVC as an input device. VB-CABLE is the recommended and primarily tested option.</p>
  </div>
  <div className="itervc-choice__card">
    <span className="itervc-choice__label">Direct playback</span>
    <h3>No — when you only want to hear the final mix</h3>
    <p>IterVC can render the mix directly to speakers, headphones, or another playback device. In this workflow, the mix is not exposed to other applications as a microphone.</p>
  </div>
</div>

## Built to stay understandable

IterVC focuses on the routing path most people actually need without requiring a full virtual mixing desk. Advanced Windows audio processing can still affect captured sound, so the documentation also covers spatial audio, surround formats, enhancements, latency, diagnostics, and common device-selection mistakes.
