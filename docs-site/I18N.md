# Internationalization plan

The site is already configured with English as the root locale, so existing URLs remain unchanged:

```text
/getting-started/quick-start/
/guides/microphone/
```

Spanish and future languages should use a path prefix while keeping the same relative file structure:

```text
src/content/docs/
├── index.mdx                         # English root locale
├── getting-started/quick-start.mdx
├── guides/microphone.mdx
└── es/
    ├── index.mdx                     # Spanish
    ├── getting-started/quick-start.mdx
    └── guides/microphone.mdx
```

This produces:

```text
/getting-started/quick-start/          # English
/es/getting-started/quick-start/       # Spanish
```

## Enable Spanish

In `astro.config.mjs`, uncomment the prepared locale:

```js
es: {
  label: 'Español',
  lang: 'es',
},
```

The Spanish sidebar labels are already included in the configuration. Once the locale is enabled, Starlight will display its language selector automatically.

## Translate progressively

Create Spanish files using the same path and filename as the English source. Starlight can fall back to the English page when a translation is missing, but it is better to enable the Spanish locale only when the key entry pages are ready:

1. Home.
2. Installation.
3. Quick start.
4. Audio devices.
5. Application audio.
6. Microphone and noise gate.
7. No-audio troubleshooting.

After that, translate the remaining guides and reference pages incrementally.

## Add another language later

Add another locale to `locales`, for example:

```js
fr: {
  label: 'Français',
  lang: 'fr',
},
```

Then create matching files under `src/content/docs/fr/`. Add the new language labels to each `translations` object used by `navLabel()` in `astro.config.mjs`.

## Translation rules

- Preserve file paths and filenames between languages.
- Keep product names, code identifiers, device names, tokens, and filesystem paths unchanged.
- Translate screenshot captions, alt text, headings, callouts, and troubleshooting steps.
- Update all language versions in the same pull request when behavior changes.
- Do not translate features from open issues until they exist in `master`.
